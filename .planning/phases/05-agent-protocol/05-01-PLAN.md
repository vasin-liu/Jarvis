    Define trait ToolCallParser with fn id(&self) -> &amp;str and fn parse(&amp;self, text: &amp;str) -> ToolCallParseOutcome.

    JsonToolCallParser (D-01..D-04, D-09):
    - Reject any text containing triple-backtick fence characters → Failed with error mentioning markdown fence not allowed (D-02).
    - Select parse target using discretion: if exactly one non-empty line exists use that line trimmed; else if trimmed whole text has no interior newlines use trimmed whole text; if multiple non-empty lines each starting with {"name" → Failed multi-object (D-03); if preamble + one JSON line heuristic from RESEARCH Open Q1: exactly one line starting with {"name" that validates → Found; multiple such lines → Failed.
    - Parse with serde_json; require name as string and arguments as object; extra keys ignored; wrong types → Failed.
    - Plain natural language with no tool intent markers → NotFound.

    XmlToolCallParser (D-07, D-10, D-15, D-16):
    - Move existing parse_tool_call tag-extraction logic unchanged for valid XML.
    - On Found emit eprintln! exactly: [jarvis] XML tool_call format deprecated; use JSON line
    - Invalid JSON inside valid tags → Failed (not NotFound).

    CompositeToolCallParser (D-08): run Json first; on NotFound try Xml; on Json Failed return Failed immediately (do not fall through to XML when JSON path detected tool intent and failed).

    Refactor tools.rs parse_tool_call to delegate to CompositeToolCallParser and return Option only when outcome is Found (backward compat for existing tests).

    Add #[cfg(test)] mod tests in tool_parse.rs covering: bare JSON line Found; XML fallback Found with deprecation path; fence → Failed; two JSON lines → Failed; missing arguments → Failed; prose → NotFound; broken JSON after {"name → Failed.
